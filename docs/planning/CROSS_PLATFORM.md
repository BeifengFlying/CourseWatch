# macOS / Windows 系统适配方案

> 2026-11-12 实现更新：当前桌面界面已采用共享 Vue 页面，macOS 使用 Swift / WebKit，Windows 新增 C# / WinForms / WebView2 外壳及 Windows CI 打包。下文保留早期设计，其中“扩展为主要界面”“不引入 C#”等取舍已被当前实现替代。当前构建方式见 [Windows 桌面版](../guides/WINDOWS.md)，验证状态见 [Windows 记录](../verification/VERIFICATION-WINDOWS.md)；Windows 实机验收仍待进行。

平台范围：**jsjks 与人卫优先，后续平台整合现有实现，软件同时面向 macOS 和 Windows 11。** Windows 目标 CPU 架构尚未核实。当前为设计，没有已经通过实机验收的应用、安装包或系统集成。

## 1. 共享业务，隔离系统能力

继续以需求中的“独立本地后台 + 浏览器扩展”为基础。任务中心使用共享 Vue 界面，后台使用共享 TypeScript 核心。应用退出浏览器后由用户级后台继续监控，不要求用户自行安装 Node、Python 或开发工具。

首批两个平台分别建立适配器：`ynjy` 负责 jsjks 教学班内作业、考试的发布与截止时间监控，`renwei` 负责人卫作业/考试信息。身份、会话与平台能力均隔离，不能因为共用界面就共用状态推断。

更新：jsjks 主站教学班及编程作业列表已只读观察到，接口、其余分类与独立会话尚待验证。长期运行需控制资源开销，首版采用独立后台与按需界面，不使用常驻 Electron 宿主或浏览器；资源预算见[轻量运行要求](RESOURCE_BUDGET.md)。

建议定义一个系统集成边界，业务代码只调用标准能力：

```text
PlatformRuntime
├── paths           用户数据 / 日志 / 浏览器配置目录
├── autostart       注册 / 查询 / 取消用户级自启动
├── notifications   权限 / 发送 / 更新 / 点击回跳
├── credentials     保存 / 读取 / 删除本地令牌
├── lifecycle       单实例 / 停止 / 崩溃恢复 / 系统恢复
├── openExternal    校验后打开平台 HTTPS 链接
└── updater         校验 / 安装 / 失败恢复
```

系统适配器只收业务参数，不接受扩展传入任意 shell 命令、文件路径或可执行程序。

## 2. 现有项目的参考方式

| 现有实现 | 复用方向 | 在桌面端的替换 |
| --- | --- | --- |
| xxt-Tool 的学习通/雨课堂 HTTP 与 HTML 解析 | 作为后续平台只读适配器移植来源 | Kotlin 网络与解析逻辑迁移到 TS，补齐错误与分页契约 |
| xxt-Tool 的 WebView 登录、Android Keystore、WorkManager | 参考登录与数据隔离流程 | Playwright 独立会话、两系统凭据后端、持久化后台调度 |
| chaoxing-journal 的未知截止与部分成功 | 参考解析和结果建模 | 抽取纯逻辑，不接入 Flutter MethodChannel |
| UniversityTodos 的多源同步、通知、托盘与安装实践 | 功能对照与系统问题清单 | Windows 专用 DPAPI/WebView2/WinRT 不作为共享 TS 核心；AGPL 实现不直接导入 |
| WXT / Playwright / Fastify / Drizzle 等 | 跨平台通用依赖 | 每个发布架构验证实际稳定版本及其原生依赖 |

桌面系统的支持应来自 CourseWatch 自身的构建与运行证据，不能继承上游 Android 或 Windows 应用的支持声明。

## 3. 系统差异与具体路径

| 能力 | macOS | Windows | 共享要求 |
| --- | --- | --- | --- |
| 用户数据 | `~/Library/Application Support/CourseWatch/` | `%LOCALAPPDATA%\CourseWatch\` | 数据与安装目录分离，不要求管理员权限 |
| 日志 | `~/Library/Logs/CourseWatch/` | 用户数据目录下 `logs\` | 轮转、容量上限、错误脱敏 |
| 自启动 | 当前用户 LaunchAgent，登录后启动 | 当前用户登录计划任务或登录启动项 | 可查询/关闭，停止监控与退出后台语义明确 |
| 崩溃恢复 | 配置 LaunchAgent 恢复策略，主动退出不形成重启循环 | 用户计划任务失败重启或用户级主管 | 有退避和错误展示，不在崩溃时无限拉起 |
| 通知 | Notification Center 后端与权限 | Windows Toast、稳定应用身份和开始菜单入口 | 能测试通知、查看失败原因，拒绝通知时仍保存通知记录 |
| 凭据 | Keychain 后端 | Credential Manager / DPAPI 后端 | 禁止硬编码密钥，密钥与密文共同存储不得作为唯一保护措施 |
| 文件权限 | profile 目录当前用户访问，敏感文件限制权限 | 当前用户目录与明确 ACL | profile 的保护边界与普通本地令牌分开说明 |
| 系统恢复 | 原生恢复事件或暂停间隔检测 | 原生恢复事件或暂停间隔检测 | 恢复后错峰扫描、提醒合并，时钟变化重新核对 |
| 外链 | 默认浏览器打开已确认 HTTPS 地址 | 默认浏览器打开已确认 HTTPS 地址 | 拒绝 `file:`、任意自定义协议和任意命令 |
| 卸载 | 取消 LaunchAgent、停止进程、移除应用 | 取消计划任务/启动项、停止进程、移除应用 | 默认保留用户数据，彻底清除需用户明确选择 |

Windows 后台应在登录用户的交互会话运行，不能默认注册为 SYSTEM 服务，否则通知与用户凭据访问可能不符合预期。计划任务必须验证触发、权限、工作目录、退出与重启行为。

macOS 自启动使用绝对程序路径，并测试应用移动或升级后的路径更新。用户明确退出后台时，应避免主管立即拉起；暂停监控、关闭界面与退出后台要使用不同状态。两系统都要求单实例和数据库写入者互斥。

## 4. 通知与桌面宿主选择

### 首选验证路径：独立 Node 后台

先用 `node-notifier` 验证两个系统的通知能力，通过 `PlatformRuntime.notifications` 封装。Windows 验证应用身份、快捷方式、用户会话与点击激活；macOS 验证通知权限、发送者身份、程序签名/分发环境和点击回跳。随包二进制许可按[开源选型](OPEN_SOURCE.md)处理。

该库是候选，不是已经验证的最终通知层。如果缺少必要能力，替换对应系统适配器，不修改任务核心。系统凭据后端所用 Node 原生封装包也应经过维护状态、许可、架构和打包验证再锁定；找不到可用安全存储时应报错或进入明确的受限模式，不能悄悄改为明文凭据。

### 界面与托盘：按需启动，首版不采用 Electron

任务管理界面按原需求在扩展中打开，关闭后不继续渲染页面或刷新日历。需要桌面启动入口时提供轻量启动器；需要托盘时优先通过最小原生桥接接入，并把辅助进程一并纳入资源统计。

Electron 已列入技术调研，但因最新轻量要求不作为首版实现路径。A 阶段验证独立 Node 包装、原生系统能力和按需 Playwright 登录；登录或必要采集结束后关闭受管浏览器。后台生命周期仍不依赖用户的 Chrome/Edge。

不优先改用 C#/Avalonia 或 Tauri/Rust，以免仅为复用某个平台界面而引入第二套核心语言和运行环境。现有需求中的共享 TypeScript、平台解耦和本地优先原则保持。

## 5. 安装与构建目标

首版构建矩阵提案：Windows 11 x64、macOS arm64、macOS x64；Windows CPU 架构需在测试设备上确认。macOS 最低版本取决于锁定的 Node、Playwright/浏览器及通知组件支持范围，完成实测后再写入下载页；不先声明所有系统版本可用。

| 产物 | 内容 | 必须验证 |
| --- | --- | --- |
| Windows 用户级安装包 | 应用、内置 Node 运行时、对应原生模块、必要浏览器运行时、启动/卸载入口 | 标准用户可安装；空白机器无需开发工具；自启动和通知身份正确 |
| macOS 应用包及分发容器 | 应用启动器、内置 Node、对应架构原生模块、必要浏览器运行时 | 签名/公证分发流程、首次启动与通知权限、LaunchAgent、升级与卸载 |
| 浏览器扩展包 | WXT 构建的 Chrome/Edge MV3 扩展 | 两系统上的安装、配对、host permission、断连状态与版本兼容 |

Playwright 浏览器可以选择随包或首次受控安装；A 阶段比较体积、离线可用性和下载失败恢复后再定。不能依赖用户的日常 Chrome profile，也不能默认使用某个在开发机存在的绝对浏览器路径。

`better-sqlite3` 等原生组件按目标系统、CPU 架构、Node ABI 构建。不能把 macOS 的 `node_modules` 直接打进 Windows 包，也不能假定单文件打包工具自动收集 SQLite 扩展与浏览器文件。安装包 PoC 必须提前于完整功能开发通过。

更新需分别处理操作系统文件占用与应用替换，校验签名/来源、版本与内容完整性。更新前停止受控进程，迁移前做一致性备份；数据库已迁移到不兼容版本时，不能只回退程序文件而忽略数据版本。

## 6. 首批双平台的实机验收

| 场景 | macOS | Windows | 平台要求 |
| --- | --- | --- | --- |
| 安装后首次启动 | 必验 | 必验 | 不要求预装 Node/Python/开发工具 |
| jsjks 官方登录与只读同步 | 必验 | 必验 | 正确识别教学班与作业/考试；验证发布发现、截止时间及截止变化 |
| 人卫官方登录与只读同步 | 必验 | 必验 | 正确识别作业/考试与详情字段 |
| 浏览器全部退出后扫描 | 必验 | 必验 | 日常 Chrome/Edge 不承担后台执行 |
| 后台崩溃与重启 | 必验 | 必验 | 缓存、历史、提醒计划一致 |
| 系统登出/登录与自启动 | 必验 | 必验 | 用户会话启动、无重复进程 |
| 休眠/唤醒、断网恢复 | 必验 | 必验 | 不误删任务，合并过期提醒 |
| 长期后台资源 | 必验 | 必验 | 记录合计内存、单核归一 CPU、扫描峰值及 24 小时增长；闲置无受管浏览器 |
| 通知拒绝、启用与点击 | 必验 | 必验 | 状态可见，点击可打开合法目标 |
| 账号切换、登出与清除会话 | 必验 | 必验 | 不串账号、不残留可导出的凭据 |
| 升级、恢复备份与卸载 | 必验 | 必验 | 正确处理路径、权限、文件锁与数据保留 |

CI 可用于跨系统构建、契约和 fixture 回放；GUI 登录、休眠、自启动与系统通知还需要目标系统实机运行证据。两平台均通过后才声明首批支持，其他平台按其整合进度分别列能力状态。
