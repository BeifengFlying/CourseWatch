## 第一章：项目定位

### 1.1 项目简介

CourseWatch 是一款面向高校学生的跨平台教学任务监控系统。

系统通过本地后台服务，自动监控多个在线教学平台中的作业、考试、测验及其他教学任务。

通过统一的数据处理机制，将分散在不同教学平台中的任务信息集中管理，并提供任务变化检测、截止时间管理、任务提醒和历史记录功能。

用户完成平台登录与监控配置后，后台定期检查教学任务；会话失效时需重新登录。

即使关闭浏览器，也不影响后台服务继续运行。

### 1.2 核心目标

CourseWatch 需要解决以下问题：

1. 不同教学平台之间任务信息分散。
2. 无法及时发现教师发布的新作业和考试。
3. 容易遗漏作业截止时间。
4. 教师修改任务时间后无法及时获知。
5. 不同平台缺少统一任务管理入口。
6. 浏览器关闭后普通插件无法持续监控。
7. 缺少统一的任务历史与变化记录。

目标架构由独立后台服务与任务中心组成，负责已接入平台的定期检查及任务管理。

### 1.3 产品设计原则

原则一：本地优先

所有核心任务数据默认保存在用户本地。

不依赖云服务器，不强制注册账号。

原则二：后台独立运行

后台服务不依赖浏览器是否开启。

浏览器扩展关闭后，监控仍然继续。

原则三：平台解耦

不同平台通过独立 Adapter 接入。

平台变化不能影响核心任务管理系统。

原则四：数据准确性优先

不能将接口异常、登录失效或解析失败误判为没有新任务。

原则五：可扩展

未来增加教学平台、消息推送方式和 AI 功能时，不需要重构整个项目。

## 第六章：平台登录与数据采集

平台登录与数据采集需分别验证会话持久化、接口覆盖和失败处理。

### 6.1 采集方式

支持三种采集方式。

HTTP Adapter

通过平台正常登录后可访问的授权接口获取数据。

特点：

- 资源占用低。
- 响应耗时需按平台实测。
- 适合定时检查。
- 不需要持续打开网页。

优先采用。

Browser Adapter

通过 Playwright 管理独立浏览器会话。

特点：

- 可以复用正常登录状态。
- 可以访问需要页面加载的数据。
- 能够处理部分动态页面。

适合 HTTP 方式无法完成的任务。

DOM Adapter

解析网页已经渲染的内容。

特点：

- 实现简单。
- 适用于缺少稳定数据接口的动态页面。
- 页面结构变化时容易失效。

作为备用方案。

### 6.2 独立浏览器配置

Playwright 使用独立的用户数据目录。

CourseWatch/
└── data/
    └── profiles/
        ├── renwei/
        ├── chaoxing/
        ├── yuketang/
        └── ynjy/

每个平台使用独立的浏览器配置。

用户首次授权时：

1. 启动平台登录窗口。
2. 用户自行登录。
3. 系统检测登录状态。
4. 保存平台会话。
5. 关闭登录窗口。
6. 后台服务后续复用该会话。

不得将浏览器会话上传至外部服务器。

不得将 Cookie 或登录令牌写入日志。

需要注意：

- 登录会话可能过期。
- 某些平台可能要求重新认证。
- 部分平台存在验证码。
- 部分平台可能限制自动化浏览器。

出现会话失效、验证码或访问限制时，应暂停采集并通知用户处理。

### 6.3 登录状态

统一状态：

type LoginStatus =
  | 'logged_in'
  | 'logged_out'
  | 'expired'
  | 'verification_required'
  | 'unknown';

平台登录失效时：

- 暂停该平台的数据采集。
- 保留已有任务。
- 记录异常。
- 发送系统通知。
- 提供重新登录入口。

其他平台继续正常运行。

## 第八章：统一任务模型

所有平台的数据都必须经过标准化处理。

interface Task {

  id: string;

  platform: string;

  platformTaskId: string;

  courseId?: string;

  course: string;

  title: string;

  type:
    | 'homework'
    | 'exam'
    | 'quiz'
    | 'activity'
    | 'announcement'
    | 'other';

  status:
    | 'upcoming'
    | 'pending'
    | 'in_progress'
    | 'completed'
    | 'expired'
    | 'cancelled'
    | 'unknown';

  publishTime?: number;

  startTime?: number;

  deadline?: number;

  duration?: number;

  creator?: string;

  url?: string;

  description?: string;

  sourceHash: string;

  createdAt: number;

  updatedAt: number;

  lastCheckedAt: number;
}

### 8.1 唯一标识

优先使用：

platform + platformTaskId

平台没有稳定 ID 时，使用经过验证的组合标识和持久化映射。

不能只根据任务名称判断唯一性。

### 8.2 时间处理

所有时间统一使用 Unix Timestamp 毫秒。

必须正确处理：

- 中国标准时间。
- 平台本地时区。
- 夏令时。
- 日期格式差异。
- 无截止时间任务。
- 无法解析的时间。

不允许将未知时间强行设置成默认值。

### 10.2 检查频率

用户可以选择：

- 5分钟。
- 15分钟。
- 30分钟。
- 60分钟。

### 10.3 任务删除

- 完整检查成功。
- 部分检查成功。
- 检查失败。
- 登录失效。
- 分页未完成。

只有确认任务确实撤回，才能标记 cancelled。

无法确认时标记为待核实。

## 第十一章：提醒与通知

### 11.1 提醒时间

时间| 提醒
新任务发布| 立即
截止前72小时| 普通

### 11.2 通知渠道

第一版：

- Windows 系统通知。
- macOS 系统通知。
- 浏览器扩展通知。

后续：

- ntfy。
- Telegram。
- 邮件。
- 企业微信。

### 11.3 通知去重

以：

taskId
+ notificationType
+ deadlineVersion

作为提醒去重依据。

截止时间修改后重新生成提醒计划。

任务完成后停止截止提醒。

### 11.4 系统休眠

系统休眠期间无法执行检查。

恢复运行后：

1. 检查系统恢复事件。
2. 立即检查各平台。
3. 恢复提醒调度。
4. 补算休眠期间已经到期的提醒。
5. 避免短时间集中发送大量过期通知。

## 第十四章：UI 设计规范

界面要求：

- 任务列表直接显示课程、类型、截止时间和完成状态。
- 提醒、平台状态与任务操作分区展示。

## 第十七章：测试标准

### 17.1 核心测试

测试| 预期结果
后台独立启动| 正常
关闭浏览器| 继续监控
关闭 Popup| 继续监控
电脑重启| 后台自动恢复
电脑休眠| 暂停监控
电脑唤醒| 恢复监控
新任务出现| 立即生成事件
DDL 变化| 记录历史
任务重复出现| 不重复创建
登录失效| 主动通知
网络异常| 不误判为无任务
平台异常| 不影响其他平台
后台崩溃| 能够恢复或提示

### 17.2 安全测试

- 本地 API 不允许外部网络访问。
- 非授权网页不能操作后台。
- 不允许读取任意本地文件。
- 不允许输出 Cookie。
- 不允许上传平台登录凭证。
- 不允许未经授权访问平台数据。

### 17.3 平台适配测试

每个平台必须有真实数据测试。

模拟数据只能用于核心系统测试，不能作为平台已经适配成功的依据。

## 第十九章：项目开发约束

以下规则必须遵守：

1. 核心后台不能依赖浏览器运行。
2. 扩展不能直接操作 SQLite。
3. 平台适配逻辑与核心模块保持隔离。
4. 不允许将模拟数据当作真实数据。
5. 不允许假设所有平台具有相同接口。
6. 不允许忽略平台登录失效。
7. 不允许错误地将空数据当作检查成功。
8. 不允许一次检查失败就删除历史任务。
9. 不允许保存明文账号密码。
10. 不允许将登录会话提交至 GitHub。
11. 不允许绕过平台访问控制。
12. 不允许在日志中输出敏感认证信息。
13. 所有时间必须统一处理。
14. 所有重要任务变化必须保存历史。
15. 所有通知必须具有去重机制。
16. 每个平台必须独立测试。
17. 每次版本更新必须提供 CHANGELOG。
18. 所有阶段必须通过验收后才能进入下一阶段。

## 第二十章：最终产品形态

CourseWatch V1.0 规划使用流程：

1. 用户安装 CourseWatch。
2. 本地后台服务自动启动。
3. 用户进入平台登录授权。
4. 启用需要监控的平台。
5. 后台服务定时检查。
6. 发现新作业和考试。
7. 记录所有任务及截止时间。
8. 检测任务时间变化。
9. 根据规则触发通知。
10. 用户通过浏览器扩展查看所有任务。

即使用户关闭 Chrome、Edge 或其他浏览器，后台监控仍然继续。

电脑保持唤醒、后台服务运行且网络可用时，按平台采集方式定期检查任务。

产品范围：已接入教学平台的本地任务检查、截止提醒与历史记录。
