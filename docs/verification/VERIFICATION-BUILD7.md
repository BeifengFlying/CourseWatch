# 构建 7 修复与双架构验证

日期：2026-11-12。版本 0.2.0，构建 7。目标为 macOS 14 及以上的 Apple Silicon（arm64）和 Intel（x64）。

## 修复范围

- API 与原生接口按已匹配路由检查权限，拒绝编码路径的未授权读写请求。
- 每次启动撤销旧原生客户端，再注册有效的新原生令牌。
- 监控来源检查解码路径和片段，采集前复查已有配置；HTTP 采集与登录探测逐跳检查重定向目标。
- 两种架构均使用独立内置 Chromium；交叉构建使用分开的浏览器缓存，并检查外壳、Node、SQLite 和 Chromium 的架构。

根因、前置条件与证据边界见[安全修复记录](SECURITY-FIX-2026-11-12.md)。

## 已完成的检查

- 11 个测试文件、82 项测试及 TypeScript 类型检查通过。
- arm64 与 x64 包内 Node／SQLite、API、网页、模拟任务、通知队列、采集子进程检查通过。
- 两种架构的包内检查均覆盖编码路径认证、普通客户端与原生客户端权限区分、旧原生令牌撤销、编码监控来源拒绝。
- 两种架构的独立 Chromium 均完成启动、静态页面渲染及关闭检查。Intel 的 Node、SQLite 与浏览器检查使用 Rosetta，不等同于 Intel Mac 实机界面、真实登录或通知验收。
- 本机 `/Applications/CourseWatch.app` 已更新到 arm64 构建 7 并启动。真实本地接口的编码路径读取、日程新增／修改／删除和原生状态／投递确认请求，无令牌均返回 401。写请求使用无效参数或不存在的 ID，没有加入测试日程或改动真实通知记录。
- 更新前后 38 条任务、0 条日程逐行一致；旧原生客户端记录已移除。已查看更新后的任务页面。旧应用、停止服务后的完整数据目录及 SQLite 一致性备份保存在本机 `.cache/pre-security-build7-20261112-184255/`，该目录不随安装包分发。

构建脚本在生成每个安装包时执行应用签名完整性和 DMG 校验，并生成对应的 SHA256 文件。只有构建成功的包作为本次交付。

- 两个 DMG 的 `hdiutil verify` 和 SHA256 对照通过；只读挂载后均确认构建号为 7，包内应用签名完整，三个关键安全修复模块与当前编译产物逐字节相同。
