# Windows 学习通登录校验

日期：2026-11-15（Asia/Shanghai）。源码版本：0.2.35，未调整版本号。

## 证据与范围

- 截图 `bcdfc8fe3679827dddf914555b9aa552.png` 显示 Chrome 中的学习通个人空间及课程卡片，应用同时提示“尚未确认登录成功”。截图未提供课程接口响应，不能据此确定接口失败原因。
- `coursewatch-system-logs.json` 记录 Windows x64、应用 0.2.35、系统浏览器模式；学习通状态为 `unknown`、`not_scanned`、未启用，日志没有学习通登录校验失败事件。云南考试系统的部分采集记录不能用于判断学习通登录结果。
- 源码原先仅通过移动课程接口确认学习通登录，网络、数据格式和认证失败统一显示未确认登录；登录校验失败由路由直接返回，未写入诊断日志。
- 未携带账号会话的只读请求验证：移动课程接口返回 HTTP 200 及要求重新登录的业务结果；网页版 `/visit/interaction` 返回 HTTP 302 至官方登录页。此检查仅确认匿名访问要求登录，不代表真实账号校验通过。

## 修改

- 移动课程接口无法读取时，使用同一会话请求官方网页版课程列表。登录确认与后台课程发现共用读取逻辑；移动接口成功时仍只请求一次。
- 网页解析依据项目已有 `third_party/chaoxing-ai-assistant/sources/course-list.js` 的原生学生课程卡片结构；要求课程列表容器、课程及班级标识、卡片标识和官方只读入口一致。隐藏卡片、空壳、退出文字及 Cookie 均不能单独确认登录。网页空容器不视为零课程。
- 限流、人工验证及请求上限仍停止读取；不访问答题、提交或修改入口。
- 登录提示区分网络、超时、响应格式和认证失败；失败保留登录窗口。诊断日志记录平台、登录校验失败事件及错误类别，不记录原始响应、课程、账号或凭据。
