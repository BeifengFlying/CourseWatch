# 2026-11-12 编码路径认证绕过修复

## 根因与影响

按一个高风险问题记录：认证钩子直接检查原始 `req.url` 中的 `/api/` 和 `/api/native/` 前缀，而 Fastify 会解码路径后匹配接口。编码 `api` 可跳过令牌检查；仅编码 `native` 时，普通配对令牌可跳过原生应用权限检查。这些情况属于同一根因。

使用旧路径判断逻辑、临时数据库和本地 Fastify 请求确认：

- `GET /%61pi/schedules` 无令牌返回 200，可读取日程。
- 日程新增、修改及删除请求无令牌返回 200，并实际改变数据库。
- 原生渲染状态写入、通知投递确认无令牌返回 200，并实际改变数据库。
- 普通配对令牌访问 `/api/%6eative/summary` 返回 200，可越过原生应用权限限制。

以上验证未使用用户的实际日程、通知队列或账号数据。未逐一执行其他业务接口；旧检查的缺陷位于全局认证钩子，不限于上述接口。

## 修复

认证钩子改用 `req.routeOptions.url`，以 Fastify 已匹配的路由定义判断 API、配对例外和原生接口权限。编码形式与普通路径执行相同的认证检查，不再由客户端提供的原始路径决定是否认证。

## 回归验证

`tests/auth-path.test.ts` 覆盖普通路径、`%61pi`、`a%70i`、完整编码的 `api`，以及 `native` 和业务路径中的编码：

- 缺少或错误令牌时，日程读取（GET／HEAD）、新增、修改及删除均返回 401；数据库保持原值。
- 原生摘要、待投递通知、渲染状态及投递确认接口，无有效令牌返回 401，普通配对令牌返回 403；拒绝请求后状态及投递记录保持原值。
- 有效配对令牌可通过编码路径读取及增删改日程；有效原生令牌可调用原生读写接口。
- 编码路径仍检查 Host、Origin 和令牌绑定来源；配对码仍校验且只能使用一次，首页和预检请求正常返回。

验证结果：`npm test` 的 10 个测试文件、67 项测试通过，其中本次新增 10 项；`npm run typecheck` 和 `npx tsc -p tsconfig.server.json` 通过。

本记录针对源码与隔离服务验证，不代表已更新现有安装应用或重新生成安装包。

## 继续检查与修复

### 原生令牌撤销遗漏

已用临时数据库复现：原生模式启动后，再用同一数据目录、不提供原生令牌或仅提供过短令牌启动，旧原生令牌仍能读取日程，返回 200。此前仅在有效新令牌存在时删除旧客户端记录。

每次启动时先撤销旧原生客户端，再按有效配置注册当前原生令牌。回归测试确认旧令牌返回 401，原生客户端标记被移除，普通配对客户端仍可读取日程但不能调用原生接口。本项需要持有旧原生令牌及发生对应启动方式切换，不是无令牌访问。

### 编码监控来源绕过操作路径过滤

已复现：持有配对令牌时，`PATCH /api/platforms/ynjy` 能保存包含 `%73ubmit` 的来源地址，绕过对 `submit` 路径的过滤。此处同属检查编码前路径的问题，但发生在监控来源配置，不能等同于此前的 API 无令牌访问。

现在共享过滤函数检查解码后的路径及路由片段，拒绝畸形编码、过深编码和原有规则禁止的操作；采集前复查已保存配置，在读取会话及启动浏览器前拒绝非法来源。测试覆盖单层／多层编码、片段路由、编码注销路径及合法列表。

未向真实教学平台发送业务写入请求，未断言这些示例地址在官方站点实际执行了提交或注销。当前过滤仍基于已知操作词，不代表能识别所有平台业务接口。

### HTTP 重定向目标检查过晚

原 HTTP 采集和账号首页探测允许自动跟随重定向，最终响应返回后才检查地址，因此不能阻止中间请求访问外站或本地地址。现在禁用自动跟随，每次请求前检查目标平台、HTTPS、端口、凭据及已知操作路径；最多跟随五次，整条链共用请求时限。官方登录页仍可用于识别会话失效。

验证使用模拟重定向链及本机临时 HTTP 服务：旧默认行为实际请求了重定向目标；修复后的调用没有请求该目标。覆盖外站、回环地址、链路本地地址、非默认端口、URL 凭据、编码操作路径、官方相对跳转及重定向循环。

尚未确认官方站点存在可利用的开放重定向；上述验证不证明真实账号已遭跨站请求，也不覆盖浏览器采集中的全部导航、脚本和子资源请求。
