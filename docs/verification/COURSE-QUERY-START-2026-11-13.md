# 单科查询、课程目录与学习启动修复

日期：2026-11-13。针对构建 16 的实际反馈修改，目标为构建 17。

## 原因与修改

- 单科请求原本带有课程 ID，但界面共享全局加载提示，接口返回所有缓存。现只返回请求范围内的结果，前端按课程合并；所点课程显示“正在查询”，其他课程保留原数据和读取时间。全部操作明确标为“查询全部课程进度”。读取失败显示在对应课程旁，重复点击不重复发请求；初始缓存读取不能覆盖随后查询的新结果。
- 部分课程默认打开“任务”而非“章节”。查询通过官网“章节”导航进入目录，等待目录 iframe 加载；该过程仅读取目录，不点击章节或播放媒体。
- 新版目录以 `.catalog_task` 提供章节完成说明，增加该结构读取。任务点计数为 0/0 时显示官网原始计数及章节状态，不推算完成率。
- 原学习启动只查顶层普通链接，无法使用 iframe 内带 `toOld` 的原生章节入口。现在在官方目录框架内查找可用章节，交由原生点击及官网跳转处理；跳过明确禁用或锁定的入口，不构造章节地址。保留页面模式不要求进入学习章节。
- 启动失败区分设置、会话、浏览器、课程入口及运行阶段；本地明确错误保留，浏览器异常转换为操作提示，不直接显示包含会话参数的地址。

## 验证

- 186 项自动测试通过；播放断言补充后，相关 17 项再次通过。覆盖单科进程参数、其他课程缓存不变、活动页切章节、0/0与章节状态分开、iframe 原生入口、跳过锁定章节、模拟正常倍速播放、错误原因及敏感地址不回显。
- `scripts/check-course-query.mjs` 检查单科加载、错误位置、重复点击、其他课程时间不变、全部查询及 0/0 文案，覆盖 1060／820／390／320px 浅色和深色，无横向溢出。截图使用模拟课程，已查看桌面浅色及窄屏深色图。
- 真实已有会话核对：“数据结构”官网默认进入任务页；切到章节后读取 19 个章节，其中 2 个有明确完成标记，官网任务点为 0/0。“基础生命科学”读取到 37 个章节、官网任务点 0/70；通过原生章节入口进入学习页，随后识别到 1 个视频。
- 真实页面核对期间抑制媒体播放，未请求模型、填入答案或提交任务。模拟播放通过及真实入口可用，不等同于真实长时间播放、自动切章或平台认可进度已验收。
