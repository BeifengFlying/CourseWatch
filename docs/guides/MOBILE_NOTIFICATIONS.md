# 手机通知与 iCloud 日历

三种渠道默认关闭，在“设置 → 手机通知”分别配置。邮件和网页推送由正在运行、联网的电脑发送；电脑休眠或关机期间不发送。电脑系统通知可以独立关闭，不影响已开启的手机通知。

## 双邮箱邮件通知

1. 准备两个不同的邮箱地址：发件邮箱、收件邮箱。收件邮箱在手机已有的邮件客户端中登录并开启通知。
2. 在发件邮箱的官方设置中开启 SMTP，按提供商要求创建授权码或应用专用密码。支持 465/TLS 和 587/STARTTLS，不允许明文 SMTP 或忽略证书验证。
3. 在 CourseWatch 选择服务预设或填写 SMTP 域名、端口、登录账号、发件地址、收件地址及授权码，勾选“开启邮件通知”，点击“保存手机通知设置”。预设只是填写服务器地址，不代表已经验证该账号可用；提供商可能另有账号要求。
4. 点击“测试邮件通知”，检查收件箱和垃圾邮件。成功消息只表示发件服务器接收，不表示收件箱已经收到或手机已经弹出。

发件邮箱与收件邮箱不能相同（不区分大小写）。收件延迟、垃圾邮件过滤、发送额度及手机邮件客户端的拉取／推送频率由服务商和系统决定。服务器、SMTP 登录账号或发件地址变化后需要重新输入授权码，防止将旧凭据发送给另一个服务器。留空保留原授权码；清除授权码前需关闭邮件通知。

授权码、推送私钥和设备订阅保存在 `notification-secrets.encrypted`，沿用 macOS Keychain + AES-GCM／Windows 当前用户 DPAPI。数据库只保存非秘密配置、设备名称及投递状态。界面和任务导出不回显上述秘密；数据库备份不包含加密凭据文件。Linux 尚未实现这套系统凭据存储。

## 网页推送

手机不需要另装接收 App，但需要支持 Web Push 的系统和浏览器。iPhone／iPad 要求 iOS／iPadOS 16.4 或更新版本，从 Safari 分享菜单“添加到主屏幕”，再从主屏幕打开并授权；普通浏览器标签页不支持这条苹果推送路径。Android 取决于浏览器、系统后台策略及推送服务的网络可达性，需在实际设备测试。

### 准备 HTTPS 订阅网页

运行 `npm run build:web` 后，将 `dist/web/mobile-push/` 目录完整部署到一个能被手机访问的 HTTPS 静态站点，例如现有站点的 `/mobile-push/`。目录包含 HTML、样式、脚本、Service Worker、manifest 和图标；保留相对路径。Service Worker 文件需要正确的 JavaScript MIME 类型，不能将不存在的文件重写成 HTML。不要给 `sw.js` 设置长期强缓存。网页无需通知中转后端，不保存平台登录信息。

应用不自动创建或发布公网站点，设备订阅需在站点部署完成后进行。普通局域网 HTTP 地址不是手机的安全上下文，不能代替 HTTPS。订阅页的 HTTPS 来源属于受信任范围，应使用由使用者管理的站点，不加载第三方脚本；站点运营者仍可能获得普通访问日志，如 IP 和访问时间。

### 配对

1. 填写 HTTPS 订阅页完整地址和推送联系邮箱，开启并保存网页推送。联系邮箱用于 VAPID 发送者标识，不会自动发送邮件。
2. 点击“生成手机配对码”，手机扫码或打开链接。每个配对码 30 分钟有效，只能导入一次；重新生成或保存设置会使原码失效。
3. iPhone／iPad 在 Safari 页面点击“复制配对码”，再添加到主屏幕并打开，粘贴刚复制的配对码。Android 可直接在支持的浏览器中操作。
4. 填写设备名称，点击“允许通知并生成订阅信息”。允许系统通知请求。
5. 复制生成的 JSON 回电脑，或保存订阅文件，通过隔空投送、已有文件传输等方式传回。在 CourseWatch 粘贴或选择文件，点击“导入订阅信息”。这一步替代常驻配对中转服务，不开放本地 API 到公网。
6. 点击“测试网页推送”，在手机通知中心核对。每台设备单独连接，最多 12 台；重复导入同一个浏览器订阅会替换原记录，避免双发。

订阅页通过浏览器系统接口联系推送服务；订阅信息不会由网页上传给 CourseWatch 开发者。请勿公开订阅文件。电脑直接向浏览器／操作系统推送服务提交加密消息，不使用 Bark、PushPlus 等通知中转套餐，但仍受苹果、Google、Mozilla 等服务和网络条件影响。失效订阅会停止发送，需重新配对。推送服务接受的消息最多保留一小时；“服务已接收”不表示手机已显示。

## macOS 写入 iCloud 日历

1. 在 Mac 系统设置中登录 Apple 账号，开启 iCloud 日历，并在系统“日历”应用确认该账号可用。iPhone／iPad 使用同一账号并开启日历同步与通知。
2. 在 CourseWatch **macOS 桌面应用**开启 iCloud 日历同步并保存，再点击“授权并同步日历”。系统会请求日历完整访问权限，用于查找、更新和移除本应用写入的事件。Windows 和普通网页不提供此授权入口。
3. CourseWatch 在 iCloud 账号下创建专用的 `CourseWatch` 日历，单向写入有明确时间、未完成的课程任务及个人日程。只修改该专用日历中带有本应用标识的事件，不编辑其他日历，也不读取 Apple 账号密码。

Mac 原生外壳约每 15 秒检查同步数据。修改时间、标题、备注或提醒规则会更新对应事件；事项完成、删除或课程移除后移除对应事件。没有明确时间的任务、首次读取时已截止的任务不写入；超过 30 天的旧事项从专用日历清理。开始时间使用截止／日程到点时间，事件长度一分钟，提醒使用该事项当前规则。

这是从 CourseWatch 向系统日历的单向同步，不会将手机日历里的编辑回写为课程任务。应用更新对应事件时可能覆盖手工修改的专用日历事件。iCloud 的上传和其他设备接收时间由系统决定，界面的“已写入”只表示 Mac 日历数据库接受了操作。

已经同步到手机的日历提醒可能在电脑关机后继续响起。关闭同步后，需要 Mac 端仍运行并保有日历权限，才能移除已写入事件；权限被撤销、iCloud 退出或应用被卸载时，不保证自动清除，可在系统日历中手动处理专用日历。若只希望电脑运行时发送通知，可以只开邮件／网页推送。

## 投递与测试范围

电脑通知、邮件、每台设备的网页推送分别记账。新开启渠道不补发历史通知；配置改变、事项完成或提醒作废会取消对应待发送记录。网络失败退避重试，最多三次；超过 24 小时的待发记录取消。远端服务超时可能发生“实际接收但未返回确认”，邮件重试仍可能产生重复；网页通知通过固定 tag 合并同条记录。
