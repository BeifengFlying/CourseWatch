# 资源占用、能耗与后台运行

适用：macOS 14+、Windows 10+ x64（最低 Windows 10 2004，Windows 实机验收待完成）。2026-11-14 的 Mac 实测使用 Apple M1 Max、32 GiB 内存、macOS 15.7.4；结果和原始汇总见 [Mac 实测记录](../verification/MACOS-PERFORMANCE-2026-11-14.md)。安装包体积、运行内存和耗电采用不同指标，浏览器移出安装包仅直接减少分发体积。

## 窗口与进程

| 状态 | macOS | Windows |
| --- | --- | --- |
| 前台 | AppKit、WKWebView 及其辅助进程、本地 Node 服务 | WinForms、WebView2 及其辅助进程、本地 Node 服务 |
| 可见但失焦 | 保留可操作的 WebView，停止界面定时请求；不因登录浏览器获得焦点而替换静态截图 | 停止界面轮询，尽力请求 WebView2 低内存模式，保留可见页面 |
| 最小化／隐藏 | 保存草稿并释放 WebView | 保存草稿并释放 WebView2 控件 |
| 关闭主窗口 | 菜单栏和 Node 后台继续；释放主窗口及对应设置页 | 首次询问关闭方式；隐藏则保留托盘和 Node、释放界面；退出则停止后台 |
| 登录／采集／学习 | 按需增加子进程和本机 Chrome／Edge；学习任务离开界面后仍继续 | 同样按需启动本机浏览器，不附带浏览器二进制 |
| 退出 | 停止自有后台、采集和学习进程 | 通过私有标准输入管道停止自有后台，超时才结束自有进程树 |

页面忙碌或草稿不能保存时暂不释放。销毁控件不保证 WebKit／WebView2 的 GPU、网络和内容辅助进程立即全部退出，运行时也可能缓存资源。资源统计需覆盖完整进程范围，包含窗口外壳及相关辅助进程。

## 后台仍然执行的工作

- 原生外壳约每 15 秒读取本地健康状态，有待投递通知时读取队列；macOS 计时器允许 3 秒合并余量。
- Node 每 15 秒检查本地截止提醒；平台调度按设置及退避决定是否采集，不是每轮都访问教学平台。课程平台在北京时间整点、半点另有补查；会话失效、人工验证或暂停监控会阻止后续自动采集。
- 前台通知、历史和日志按需读取；失焦停止界面轮询。打开菜单栏学习预览时每 2 秒读取一次摘要，收起后停止。
- U校园后台保活仍有浏览器引擎，每 5 分钟触发活动；普通超时提示及时处理。暂停停止保活；只有“打开运行窗口”才转到可见浏览器并暂停。
- “暂停监控”不停止本地提醒、Node 或已经开始的采集。关闭系统通知只影响通知投递，不停止其他工作。需要结束常驻进程时从菜单栏／托盘退出应用。

磨砂玻璃默认关闭。持续绘制、半透明合成、网页加载、网络和媒体解码均产生资源开销。释放窗口仅减少界面开销，后台任务仍按配置运行。

## Mac 实测

2026-11-14，**MacBook Pro（M1 Max，32 GiB，macOS 15.7.4）**。使用构建 30 生产代码的隔离副本、100 条模拟日程；无课程账号、无模型请求，保留正常后台提醒调度。每种状态预热 15 秒后测 120 秒，每 2 秒采样，纳入外壳、Node 和可归属的 WebKit 辅助进程。

| 状态 | CPU 均值 | RSS 均值 | physical footprint 均值 | 进程数 |
| --- | ---: | ---: | ---: | ---: |
| 前台空闲 | 0.022% | 302.7 MiB | 169.3 MiB | 5 |
| 最小化 | 0.015% | 183.2 MiB | 76.3 MiB | 2–3 |
| 关闭主窗口 | 0.015% | 167.5 MiB | 70.1 MiB | 2 |

CPU 的 100% 表示一个逻辑核；RSS 合计可能重复统计共享页。前台 60 个采样点均有 WebView，最小化和关闭窗口后均已释放；辅助进程不保证同步退出。现有 0.2.29 实例及浏览器另作观察，工作状态未控制，表中无账号空闲数据不适用于真实采集或学习负载。

另一次管理员授权的芯片功率采样：83 次、约 7 分钟，CPU + GPU + ANE 全机组件估算平均 **2.39 W**，观察范围 **1.81–3.48 W**。该统计包含其他应用和已有学习任务，属于系统芯片组件估算功率。没有关闭应用的同条件对照，不给出节电比例或续航结论。功耗采样已结束，未保留特权助手或修改系统权限。

[完整方法、观察峰值与限制](../verification/MACOS-PERFORMANCE-2026-11-14.md) · [CPU／内存汇总](../verification/macos-performance-2026-11-14.json) · [芯片功率汇总](../verification/macos-power-2026-11-14.json)。

测试副本的应用身份、服务端口和数据目录均独立。同期运行的应用与学习任务未停止或重新配置，仅作为非受控运行观察。

统计包括外壳、Node 进程树，以及按 macOS 责任进程归属的 WebKit／浏览器／解码辅助进程。CPU 按两端均存在、启动标识相同的进程 CPU 时间差计算；**100% 表示一个逻辑核**，不是整机 CPU 百分比。RSS 合计会重复统计共享页；physical footprint 是系统报告的内存记账指标，不能与 RSS 或 Windows 私有提交字节直接互换。两次采样间启动又退出的短命进程不计入 CPU 差值；峰值是采样点观察值，不是连续采集的绝对峰值。

功率使用本次管理员授权的有限 `powermetrics` 采样，CPU／GPU／ANE 合计是**芯片相关组件的全机估算功率**，包含其他应用、现有学习任务及采样开销。它不是 CourseWatch 单应用瓦数，也不是含屏幕、内存等所有组件的整机输入功率。CPU／内存复测与功率采样分开进行，不按窗口状态归因功率差异；没有关闭 CourseWatch 的同条件对照，不能声称节电比例或续航改善。

未测项目包括 10 分钟／24 小时稳定性、完整真实课程采集峰值、标准化视频播放功耗、温度与风扇、放电续航及 Intel Mac。结果适用于本报告列明的设备与短时测试条件。

## Windows 与其他缺项

Windows CI 已加入前台、最小化及关闭到托盘的短时全进程树采样，输出 `coursewatch-win-diagnostics/resources.json`；账单与支出限制曾阻止相关 CI 作业运行，已添加的采样代码尚无对应实测结果。Windows 安装包在 Windows 环境独立构建，本报告未取得对应实测数据。[既有 Windows 验证记录](../verification/VERIFICATION-WINDOWS.md)。

Windows 工作集合计同样可能重复计算共享页；`privateBytes` 是私有提交字节。旧 CI 每个 CPU 窗口约 3 秒，不代表 Windows 10／11 笔记本、10 分钟空闲或真实账号采集结果。[资源预算](../planning/RESOURCE_BUDGET.md)中的目标仍是待验收目标。

## 复现

```sh
npm run build:web
npm run build:server
python3 scripts/measure-macos.py               # 普通权限：CPU、内存、唤醒
python3 scripts/measure-macos.py --with-power  # 可选系统授权：增加芯片功率
```

重复运行前移走 `.cache/macos-performance`，保留旧结果。临时副本通过 LaunchServices 启动，使用不同身份和端口 17401；生产数据库、浏览器资料和用户学习状态不读取、不修改。原始采样与系统进程信息只放 `.cache`，公开 JSON 只保留汇总。

控制／状态记录每 0.5 秒执行一次，是测试副本额外开销；不在分发应用中。可选功率采样有固定次数，不安装特权助手，不修改账户、sudoers 或应用权限；结束后进程退出并执行 `sudo -k`。当前已完成测试的授权不会用于后续操作。

若需续航结论，应在同机、同电源模式、亮度、网络和其他负载下，做有／无 CourseWatch 的重复对照，并分别测空闲、采集和学习。现有 CPU 时间、唤醒频率、系统能耗影响和芯片瓦数不能直接换算为每小时电池下降。
